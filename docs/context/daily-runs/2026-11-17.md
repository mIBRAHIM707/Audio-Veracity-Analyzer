## Task 6.1 — bridged call between two SIP endpoints with PBX-forced codecs (partial; box unchecked)

- Requirement: PRD FR-T1 ("Asterisk PBX, two or more SIP softphone endpoints, and a call
  generator ... with codec forcing for G.711 and GSM"); plan item 3.2. Tracked under #4.
- Paths: `lab/asterisk/config/pjsip.conf` (`agent_alaw`, `agent_gsm`),
  `lab/asterisk/config/extensions.conf` (`_81[01]`, `[lab-agent]`,
  `[lab-agent-answered]`), `lab/asterisk/sipp/uas_agent.xml` (new),
  `lab/asterisk/README.md`, `tests/lab/test_bridged_call_lab.py` (new), context docs.
- Behaviour: extension 810/811 dials a SIPp UAS agent allowed one codec (A-law or GSM)
  and bridges it to a mu-law caller (60 s `L()` cap). The agent answers with that codec
  and echoes RTP. MixMonitor records both directions on the agent leg and the return
  direction on the caller leg; a `U()` hook writes the agent leg's native format;
  `DIALSTATUS` is written when Dial returns with the caller still up.
- Measured (Asterisk 20.6 / SIPp 3.7.2 lab image, rebuilt today): the agent's INVITE
  offers only the forced codec plus telephone-event 101. Asterisk translates mu-law to
  A-law directly, so the A-law agent leg carries A-law-quantised audio. The A-law agent
  leg, its echo and the caller leg's return audio are sample-identical to the G.711
  round trips. For GSM, the agent leg gets the mu-law decode exactly; the echo is
  sample-identical to a libgsm (pinned ffmpeg) encode of exactly what the encoder
  received, and the caller leg carries that decode. Each echo recording begins with
  one silent 20 ms block, then every echoed frame (no sample skipped in any check).
  Over UDP a missing agent is not detected: Dial rings out for 30 s (`NOANSWER`).
- Tests (Claude-authored, 17 Nov): 3 lab cases (A-law, GSM, unreachable agent) with
  agent port checks (`/proc/net/udp`), the agent's exit after BYE awaited, cleanup by

  `agent_alaw` fails the A-law case.
