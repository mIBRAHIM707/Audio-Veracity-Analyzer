- Tests (Claude-authored, 21 Nov; not Astra). Unlike LB07/LB10/LB12/HM02, which fake

  - RC01: the real API is killed under an open live board and started again on the
    same port. The page:
    - says it is disconnected and keeps the last state;
    - makes at least two more attempts while the port is dead;
    - reconnects by itself and takes the new API's snapshot (its call is shown and
      the dead process's call is no longer active);
    - receives live events again.
    It then checks an alert open across the restart: it stays open through a
    `stream.gap` re-read and clears only when `alert.cleared` arrives.
  - RC02, on PostgreSQL 16: the API is killed under the history page. Refresh and
    Search show "could not be reached" with no old rows. After a restart on the same

    service workers blocked. Nothing is requested elsewhere, every asset loads, and the
    stylesheet applies.

  never-cleared alert "Cleared" because the open count was 0. RC01 failed with
  `Received string: "Cleared rc01-cont (caller) ..."`.
  - Fix: for such a call, an alert raised before `started_ts`, or of unknown time, keeps
    its page state; only `alert.cleared` clears it.
  - Trade-off (documented): an alert cleared while the page was disconnected may stay
